# ProcessPrefBench 手机优先主页实施计划

记录时间：2026-10-09

**Goal:** 给海报提供可持续更新的公开主页，首屏可找到 Paper、Code、Product、Contact。

**Architecture:** 在公开研究仓库的独立分支新增 `website/`，以静态 HTML/CSS 提供内容；Vercel 仅发布该目录。固定正式域名后生成二维码，页面更新不改变入口。

**Tech Stack:** HTML、CSS、少量渐进增强 JavaScript、Vercel、Playwright。

## 已同意的设计

- 英文、手机优先，暖白/深绿视觉与海报关联；首屏以研究标题、短解释和四入口为中心。
- Paper 提供已确认的最终论文 PDF；Code 准确标注公开仓库仍为 pre-release。
- Product 介绍 Margin 与研究的关系并链接既有产品页面；Contact 使用论文已公开的作者邮箱。
- 首版不依赖待拍摄的视频，不公开原始用户数据，不改变海报现有排版。
- 优先 `processprefbench.vercel.app`，若未获得不能把候选地址写成已上线；二维码直接编码验收通过的正式地址。

## 实施任务

- [ ] 1. 检查公开仓库最新状态及 baseline validator，核对 PDF、作者、邮箱、产品链接。
- [ ] 2. 新增 `website/index.html`、`styles.css`、`main.js`、`assets/favicon.svg`、`paper.pdf`；补网站维护文档和忽略规则。
- [ ] 3. 本地服务器提供页面；在 320/375/390/430/768/1280 宽度验证溢出、四入口、触控尺寸、PDF 和联系交互；截取并人工查看手机和桌面图片。
- [ ] 4. 检查差异和发布内容，运行公开仓库 validator，提交限定文件到 `codex/processprefbench-homepage` 并推送该分支。
- [ ] 5. 独立 Vercel 项目仅部署 `website/`，验证未登录访问正式网址和四入口；用正式地址生成 SVG/PNG 二维码，并测试解码。
- [ ] 6. 补日期、commit、部署网址、验证证据与后续更新步骤。打开主页供用户查看，报告准确发布状态。

## 验证与边界

本次只新增静态网页，采用页面 smoke 与针对性浏览器验收，不运行研究模型评测。网址与产品/仓库发布状态为当日快照，可能变化。实体印刷扫码另需打样，软件解码不能代替纸张扫码。
